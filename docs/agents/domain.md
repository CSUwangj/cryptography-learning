# Domain Docs

Before exploring the codebase, read `CONTEXT.md` and any relevant records under `docs/adr/`.
If either location does not exist, proceed without treating its absence as an error.

Use the glossary's terminology in issue titles, specifications, tests, and implementation.
If proposed work contradicts an existing architectural decision, surface the conflict rather
than silently overriding it.

This is a single-context repository. Domain terms belong in the root `CONTEXT.md`, and
repository-wide architectural decisions belong under `docs/adr/`.
